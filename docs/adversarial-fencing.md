# Adversarial fencing verification

This repository treats a Fiducia lease grant as temporary authority, not as a
standalone write permission. A protected datastore must compare and advance the
resource's durable fencing watermark atomically with the protected mutation.
The adversarial suite checks that rule at three independent boundaries:

1. the pure Rust, Go, TypeScript, Dart, and Gleam decision implementations;
2. PostgreSQL, including Supabase- and Neon-compatible `NUMERIC(20,0)` state;
3. Redis-resident state guarded by one same-slot Lua script.

## Reproducible corpus

`conformance/cases/fence-adversarial.json` is generated by
`scripts/generate-fence-adversarial.py`. The generator implements SplitMix64
locally; it does not depend on Python's `random` implementation. `conformance/cases/fence-adversarial.json` is a small, tracked smoke
corpus so direct per-language test commands still work. Pull-request CI
regenerates a capped 128-random-case corpus under `target/` and points every
runtime at that exact file; the weekly schedule uses 2,048 random cases. The
pinned configuration is:

```text
seed: 0x4f5245534c4f434b
tracked smoke random cases: 1
tracked smoke sha256: 0eb341b157b2f7b79e14e2c0889c787ce503e9187efaef46a16c2f2265867a11
pull-request random cases: 128
pull-request sha256: 660093a8e70491c268341ae94a740f8f68e2751badd29a2da37ac9a2489a6cbf
scheduled random cases: 2048
```

The generated corpus covers zero, JavaScript's exact-integer boundary, signed-64 boundaries, the
full unsigned-64 maximum, random neighbors, replay versus token reuse,
identity mismatch, invalid decimal forms, Unicode lookalike digits, and UTF-8
byte-length boundaries. Every runtime consumes the same tracked file. The
TypeScript and Go wire tests add hostile runtime-object/JSON cases that cannot
be represented as typed Rust, Dart, or Gleam values.

Regenerate and verify the tracked corpus with:

```sh
python3 scripts/generate-fence-adversarial.py \
  --seed 0x4f5245534c4f434b \
  --cases 1 \
  --smoke \
  --output conformance/cases/fence-adversarial.json
python3 scripts/generate-fence-adversarial.py \
  --seed 0x4f5245534c4f434b \
  --cases 1 \
  --smoke \
  --check conformance/cases/fence-adversarial.json
```

Pull-request and scheduled workflows write their larger deterministic corpus
under `target/fence-adversarial/` and export its path to all five runtimes. They
do not modify or commit the tracked smoke corpus.

## PostgreSQL adversaries

The PostgreSQL suite proves:

- `(tenant_scope, resource_key)` is a structural tuple, not a concatenated key;
- byte limits behave consistently for multibyte UTF-8 input;
- concurrent first writers serialize and the greatest token remains current;
- a transaction rollback removes the watermark, protected state, and receipt;
- full-width unsigned tokens remain exact in `NUMERIC(20,0)`; and
- malformed persisted authority state fails closed and is not silently
  repaired by a newer incoming token.

The last property is defense in depth for old migrations, manual DBA changes,
constraint-disabled imports, logical replication, and damaged restores. Normal
writes remain protected by table constraints as well.

A Supabase decision does not authorize a Neon write, and a Neon decision does
not authorize a Supabase write. Each physical writable PostgreSQL database
installs and evaluates its own watermark in the same transaction as its local
mutation. Applications needing one canonical outcome must choose one write
authority and replicate through an outbox/opto-sync flow rather than claiming a
cross-provider ACID transaction.

## Redis adversaries and failure boundary

The Redis script rejects, before its first mutation:

- aliased watermark/state keys;
- missing or different Redis Cluster hash tags;
- wrong key types;
- orphan state or orphan watermark keys;
- missing, extra, or malformed persisted watermark fields; and
- malformed incoming token, operation, payload digest, holder, or lease id.

It also races 32 independent first writers and proves that the greatest token
wins, stale writes do not change state, and an exact replay does not reapply the
protected value.

Redis Lua execution is atomic with respect to other clients, but Redis does not
roll back commands already executed if a later command raises a runtime error.
The script therefore completes every deterministic validation and key-type
check before `HSET`. If an infrastructure failure interrupts the final
`HSET`/`SET` pair, the next invocation detects the orphan invariant and fails
closed; it never silently repairs partial authority state. Redis remains
appropriate only for Redis-resident protected state and is never the sole fence
for a later PostgreSQL mutation.

## Machine-readable admission receipt

The main CI workflow adds a final receipt job that depends on Rust, Go,
TypeScript, Dart, Gleam, persistence, and peer-contract jobs. It records the
exact revision, corpus digest and seed, per-boundary conclusions, and whether
all expected checks completed successfully. Any missing, skipped, canceled, or
failed required job produces `stopped_for_evaluation` and blocks merge.

The receipt does not elevate generated fixtures into a contract authority.
`contracts/typespec/main.tsp` and
`contracts/json-schema/contract.schema.json` remain independently authored peer
authorities with no precedence between them.
